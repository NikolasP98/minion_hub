## Scheduling and rollback

The same authenticated `GET /api/pulse/tick` first collects due sources, then drains only configured Pulse families within fifty seconds. Query selectors are rejected. First collection is immediate, success waits fifteen minutes, failure waits five minutes, and a durable thirty-second generation lease serializes concurrent collectors. Collection performs no reasoning and advances no accepted cursor.

`deploy/pulse-tick.cron.example` is an uninstalled minute schedule. `scripts/ops/pulse-tick.sh` requires `CRON_SECRET` and `MINION_PULSE_TICK_URL` from the existing secret manager. The endpoint must be exact HTTPS `/api/pulse/tick`; loopback HTTP is accepted only for local tests. The script does not follow redirects, print credentials or install a schedule.

Retain `MINION_PULSE_DIGEST_SCOPE='{"tenantId":"<personal-org UUID>","ownerProfileId":"<owner UUID>"}'` separately from the policy. An enabled policy must match this exact trusted binding. When the explicit scope is absent, the existing strict D worker configuration may provide the same binding. A malformed explicit scope never falls back to D; disagreement denies the tick. This representation refines the approved fixed-target cleanup contract: policy deletion or corruption after a cold restart can fence only the retained owner, with no tenant discovery or caller-selected scope. Removing the policy must leave the scope configured. Do not move scope by editing a policy. Retire/cancel the old namespace and retain its accounting evidence before a separately approved owner/scope migration; there is no automatic rebind or replay reset.

Before activation, qualify the exact deployed source/migration/lock/SDK identities, current personal owner, exact approved source policy and output/price exposure. Apply the ordinary guarded Hub migration runner, verify the paired QA seed twice, configure the trusted policy, then obtain separate human approval for owner activation and schedule installation. No command in this document installs cron or calls a paid model.

To disable, set the trusted policy `enabled:false` and invoke the authenticated tick. Queued work is canceled and collection/job generations are fenced; admitted uncertainty remains reserved. Membership deletion uses the existing shared cancellation path. Keep the additive schema and minimal billing/replay evidence when rolling back. Do not deploy an older binary that can retry admitted attempts. Raw evidence, provider bodies and feedback comments are redacted after thirty days by bounded tick housekeeping. Housekeeping uses only the validated retained scope, including after policy removal, approval expiry or module disablement; absent, malformed or mismatching scope denies it. Each tick clears at most one hundred raw records across dispatch, digest runs, source evidence and feedback, within the shared monotonic deadline. A late expired response retains its bound billing facts and replay fence without restoring the response body. A replay namespace must be retired before tombstones can be removed; unresolved accounting cannot be discarded.
