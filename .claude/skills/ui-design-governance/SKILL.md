# UI Design Governance — Minion Hub + Site

One design system, machine-enforced. Semantic tokens and shared primitives only; raw values and hand-rolled copies are regressions that fail gates.

**Violating the letter of these rules is violating the spirit of these rules.**

## Authority chain (highest first)

1. `packages/design-tokens/contract.json` (meta-repo) — machine truth. 16 themes × 43 resolved tokens, 10 accent pairs, 34 compat aliases. `tokens.css` is **generated** (`pnpm --filter @minion-stack/design-tokens generate`); `utilities.css` is hand-authored in the same package. Build fails on stale CSS, incomplete theme, unknown alias, or <AA contrast.
2. `specs/2026-07-13-hub-ui-coherence-implementation-spec.md` §D2 (meta-repo) — sole normative naming policy. §D3 theme, §D4 typography, §D5 primitives, §D6 layout/archetypes, §D9 a11y.
3. `minion_hub/scripts/DESIGN-LINT.md` — enforcement mechanics.

## Iron rules

- **Semantic tokens only.** Never a literal hex/rgb, Tailwind palette utility (`bg-slate-500`), arbitrary size (`text-[16px]`, `p-[13px]`), raw shadow, raw duration/easing, or numeric z-index in `.svelte` files. Raw colors are legal only in `app.css` and `themes/*.ts`.
- **⛔ Forbidden names (hard-fail):** `--accent`, `--accent-bg`, `--accent-rgb`, `--color-background`, `--color-bg1`, `--color-error`, `--color-primary`, `--color-primary-foreground`. Migrate consumers to the semantic role; never re-declare these.
- **Never hand-edit `tokens.css`.** Extend `contract.json` and regenerate.
- **Theme = `data-theme` on `<html>` only.** No Tailwind `dark:` variants (dead code here — no class/media wiring), no `prefers-color-scheme`, no per-theme selectors in components. Components read semantic tokens; themes swap the values.
- **Accent is a pair.** `--color-accent` always with `--color-on-accent`. Categorical `--color-purple/pink/cyan/emerald/neutral` are for charts/data-viz ONLY, never action or status semantics.
- **On-accent prefers white** (user directive 2026-07-16): white text whenever it clears AA 4.5 on the accent; black ONLY on bright accents where white can't (amber/cyan/green/orange). Dark accent options are tuned to 600-scale shades so white passes — never "fix" contrast by flipping a dark accent back to black text, and never pick on-accent by raw max-contrast (`onAccentFor` in hub encodes the white-first rule).
- **Compat aliases** (`--color-bg`, `--color-foreground`, `--color-muted`, `--shadow-sm`, `--hairline`, …) are legal but write new code with the canonical names.
- **Text tokens never paint surfaces.** `--color-text-*` — and their aliases `--color-muted` (→text-secondary), `--color-foreground` (→text-primary) — are foreground-only. As a `background` they render dark-gray panels under dark text on light themes (shipped: unreadable chat bubbles, note cards, score tracks). Surfaces come only from `--color-canvas`, `--color-surface-1..3`, `--color-overlay`; dim indicator DOTS may use text colors (the `--color-status-idle` precedent), panels never.

## Layout contracts (root-caused 2026-07-15 — violating these caused 7 shipped bugs)

- **One scroll owner per screen** (spec §D6). The module content pane owns scroll (`overflow-y-auto` on the page body); the section nav NEVER scrolls with content. If scrolling drags the section nav away, scroll ownership has silently fallen through to `route-viewport` — the shell chain lost its height bound somewhere above.
- **The `(app)/+layout.svelte` fade-wrapper must stay `flex flex-col`.** Every `SectionShell`/`PageShell` below it relies on `flex: 1` for viewport-height lock; a plain block wrapper makes all of them size to content (symptoms: section nav ends mid-panel, `overflow-y-auto` panes never activate, page bottoms clip).
- **Page roots inside a `SectionShell` must fill the row**: use `PageShell` (has `flex: 1`), or put `flex-1 min-w-0` on a bare root div. `class="flex flex-col h-full min-h-0"` alone shrinks to intrinsic width in the shell's flex-row — and a narrow container trips `EditableGrid`'s container query into single-column stacking. If a dashboard collapses to one column, check the container width before blaming the grid.
- **`Button` slot trap**: `@minion-stack/ui` Button renders slotted children inside an inner fixed-height `inline-flex` row `<span>`. Consumer classes (`flex-col`, `truncate`, `!h-auto`) on the Button do NOT reach it. For card-shaped buttons, override via a scoped ancestor: `.wrapper :global(.myclass > span) { flex-direction: column; width: 100%; align-items: stretch; }` and `height: auto` on the button itself (see POS sell `.card`, appearance `.theme-card`).
- **Svelte scoping needs a real ancestor anchor for component children.** `.a :global(.b)` matches only if `.b` is a DESCENDANT of a scoped `.a` element. A rule targeting a component's forwarded class placed next to (not inside) the anchor silently never applies — wrap the component in a scoped element and anchor on that (see ShiftBanner `.mini-rail`).
- **Forwarded-class contract**: ANY class passed as a prop to a shared primitive (`Button`, `Badge`, …) is invisible to plain scoped CSS — the rule compiles and ships dead. Always write it as `.scoped-ancestor :global(.class)`, and remember the primitive's inner row `<span>` needs its own `> span` rule for alignment. Five separate visual bugs shipped from one file (DataTable) this way; if a style "isn't taking" on a primitive, check the served CSS hash before adding `!important`.
- **Selection-control contract**: checkbox-like affordances are a fixed `1rem` border-box in BOTH states (checked must never resize) — unchecked `--color-border-strong` border on `--color-surface-2`; checked/indeterminate `--color-accent` fill + `--color-on-accent` mark; row hover promotes the unchecked border to accent so the affordance is discoverable (see DataTable `.dt-check`).
- **Floating-panel dismissal contract**: NEVER dismiss a panel with a `position: fixed` backdrop element — any ancestor with `backdrop-filter`, `filter`, or `transform` (e.g. a sticky blurred `<thead>`) becomes its containing block and silently shrinks the "viewport" backdrop to that ancestor's box, breaking click-outside. Use a `<svelte:document onpointerdown>` outside-click listener + Escape, or the Zag `Dropdown`/`Popover` wrappers which provide both. A hand-rolled `{#if open}` menu with NO dismissal mechanism at all is the same bug class (shipped: TeamTab kebab) — every open-able panel names its close paths (outside-pointerdown + Escape) or uses a Zag wrapper.
- **A backdrop also hijacks the cursor**: a viewport-sized `Button` backdrop keeps `cursor: pointer` over the WHOLE page while the menu is open (shipped: DataTable column menu + header context menu, owner 2026-09-29: "the cursor only appears as a pointer when it's directly hovering over the clickable element"). Pointer cursors belong to the hovered clickable row/option only — never to a panel body or a dismiss layer; dismiss with the document listener above.
- **Nested floating panels paint above their host**: `Dropdown`/`Popover`/`Tooltip` all sit at `--layer-modal`; a panel opened from INSIDE another panel gets `calc(var(--layer-modal) + 1)`. `portalInLayer` decides `nested` BEFORE the portal moves the node (afterwards the host is no longer an ancestor) and writes the level on the CONTENT element: Zag copies the content's computed z-index onto the positioner and re-spreads the positioner's inline style on every reposition, so a positioner-only write is wiped on the first move (shipped twice: FilterChip's "…" menu under its popover; then every Dropdown under the sticky table header).
- **List-selection contract** (root-caused 2026-07-16, settings/plugins): a selected row in a nav/list surface is an accent-TINTED surface + accent text (`bg-accent/10` or `color-mix(… var(--color-accent) 10% …)` + `--color-accent` on the title; secondary lines stay `--color-text-secondary`). A FULL `--color-accent` fill with `--color-on-accent` text is reserved for primary-action buttons and small selection-control marks — painting a whole list row with it drowns icons/status dots and reads near-black-on-blue on most themes (Button `variant="primary"` is an action style, not a selection style).
- **Canvas charts need concrete colors** (re-broken 2026-07-16, reliability): anything handed to a canvas renderer — ECharts `itemStyle`, series palettes, sankey node colors — must be a RESOLVED string via `cssVar()`/`chartColors()` (`$lib/utils/chart-colors`); a raw `'var(--token)'` string silently renders gray, and sankey `lineStyle.color:'gradient'` throws on it and blanks the whole series. DOM-side inline styles and HTML tooltip strings may keep `var()`. The token sweep that "normalized" chart hexes to `var()` strings caused this — normalizing INTO `cssVar()` is the correct move.
- **Sticky elements need an opaque surface.** A `position: sticky` header painted with a transparent variant (Button `outline` is `bg-transparent`) lets scrolling content render through it (shipped: config editor group headers). Sticky = explicit `--color-surface-*` background, always.
- **Bar-row list contract** (user directive 2026-07-16, CRM dashboard): rows of label + value + horizontal bar read as `label | value(s) | bar` — numbers sit LEFT of the bar and the bar is the LAST element, growing rightward on the `1fr` track. Bars must share one aligned start x: the CONTAINER owns the column tracks (`display:grid; grid-template-columns: max-content … 1fr`) and each row is `grid-template-columns: subgrid; grid-column: 1 / -1`. Per-row grids size their own label columns → staggered bars (shipped: ETAPAS DEL CICLO). Reference: crm/+page.svelte `.funnel`/`.chmix`.
- **Detail-card header contract** (owner directive 2026-09-17, CRM contact page): every card on a record-detail page shares ONE header shape — `.card-h` uppercase caption title on the left and at most ONE link-style action on the right (accent caption text: a plain `<a>` or a `Button variant="ghost"` collapsed to `height:auto; min-height:0; padding:0` with inherited transform/weight), exactly like the bookings card's "New appointment". Never an outlined button, a hint caption or any second line inside a card header; supplementary hints (size limits, accepted types) go in a `Tooltip` on the action (`AttachmentButton hint="tooltip"`). Side-by-side cards must share header height.
- **Stale-while-revalidate lists**: a component that refetches inside an `$effect` keeps its current rows/empty state on screen while the refetch is in flight — only the FIRST load may render nothing. Gate empty states on a `loaded` flag set once, never on `!loading` (shipped: "No attachments yet." blinking on the contact page's 12 s background refresh).
- **One chip contract, app-wide** (owner 2026-09-29: "use the same chip styling for the entire app"): `Chip`, `TagChip`, `FilterChip` and the `GroupByPicker` pill all render through the shared `.chip`/`.chip-x` recipe in `app.css` — `--radius-full` pill at `--control-height-xs`, `1px` `--hairline` on `--color-surface-2`; active = accent-tinted background + accent border/label; the × is icon-sized with a ROUND hover surface (`color-mix(accent 12%)`), reveals on chip hover/focus-within into a slot reserved ONLY when `removable` (no reflow), and is always visible under `(hover: none)`. **The label never moves** — a `translateX` "recentre" at rest that snaps back on hover reads as misaligned text with the × landing on it (shipped: the "AH" tag). A component's own scoped padding out-specifies the shared `.chip-removable` rule — override at matching specificity (`.tag-chip.chip-removable`), never by copying the recipe. Shipped violation: FilterChip's square gray hover box inside a rounded pill.
- **Severity/status ramp is one fixed semantic map** (user directive 2026-07-16, reliability): a severity/status LEVEL (critical/high/medium/low/info/ok, or any enum) maps to ONE semantic status token and reads the SAME hue on every surface — table chip, chart series, sankey node, filter-dropdown dot, legend. Never let a chip palette drift from the chart palette (shipped: `info` was `bg-accent`/red in the table chip but `--color-info-fg`/blue in the dropdown+sankey — same level, two colours). Map to status tokens only (`danger`/`warning`/`info`/`success` + `neutral`/surface for the calm steps); **never `--color-accent` for a status level** — accent is a primary-action colour, and painting a status with it both breaks the pair rule and reads as a false alarm (red info). Canonical hub ramp: critical→danger, high/medium→warning, low→neutral/surface, info→info, ok→success. When two levels share a token (medium/high both warning), that is acceptable if the label disambiguates; a wrong-hue is not.
- **Personalized nav order applies in EVERY nav renderer** (root-caused 2026-07-19): the user's drag-reordered sidebar order lives in prefs (`navOrder`) and is applied through the shared `layout/nav-order.ts` helper (`readNavOrder` + `orderSections`/`orderItems`). The desktop `Sidebar` AND the mobile hamburger (`Topbar`) must both sort through it — a renderer that iterates raw `getSections()`/`section.items` silently ships a DIFFERENT order (shipped: the mobile menu ignored the reorder while desktop honoured it). Editing (native HTML5 drag) stays desktop-only, but the read+sort is shared; any new surface that lists nav sections/items sorts via `nav-order.ts`.
- **Segmented toggles use `SegmentedControl`; date ranges are inclusive** (root-caused 2026-07-19, /finances). (a) Any small mutually-exclusive choice (chart mode, revenue/qty, period, quick-range) is a bordered pill group whose ACTIVE option is an accent-TINTED pill + accent text (`bg-accent/14` + `--color-accent`) — NEVER a full-accent-fill `Button variant="primary"` (that's an action style; shipped inconsistently across /finances toggles). Use `SegmentedControl`, don't hand-roll `Button primary/ghost` rows. (b) Every dashboard's date picking uses `DateRangeControls` (from/to + quick + ⋯/right-click extended-range menu + SMART period picker that disables/snaps granularities too coarse for the span via `date-range.ts`), rolling-12-month default. (c) Range inclusivity is its own contract — see the next bullet.
- **EVERY range filter is INCLUSIVE of both endpoints** (root-caused 2026-07-19 /finances; re-audited 2026-08-01 across the hub). A user who picks `Jun 1 → Jun 30`, `score 0 → 100`, or reads the last column of a heatmap means those endpoints are IN the result. **The comparison operator alone never decides this — the bound's TYPE does**, so pick the idiom by column type:
  - **`date` column + `'YYYY-MM-DD'` bound** → `col >= from AND col <= to` is genuinely whole-day inclusive. Correct as-is (meta ad/post insights).
  - **timestamp column + day bound** → NEVER `<= to`: a midnight `to` matches only that day's `00:00:00.000` rows. Use the half-open `col >= from AND col < (to + 1 day)`, resolving the boundary in the org's BUSINESS timezone via `zonedDayWindow()` / `resolvePeriodWindow()` — a UTC day window drops a 19:30 Lima sale. Document on the function that its window is `[from, to)` and that `to` is the start of the day AFTER the last covered one.
  - **JS-side filtering** → `toTimestamps()` (widens a date-only `to` to `T23:59:59.999`). Never hand-roll `T23:59:59` — it silently drops the final second.
  - **API query params** → `parseInclusiveEnd()` at the parse boundary. A bare `new Date(param)` on `?to=2026-05-31` is midnight and loses the whole day.
  - **numeric / non-date ranges** (min–max score, amount, count, duration) → closed on both sides: `>= min AND <= max`. Same rule, no date involved.
  - Shipped failures of this exact contract: `/socials/ad-performance` used `date < to` and dropped May 31; the `/scheduling` utilization heatmap passed a midnight `to` to `lte(start_time, to)`, so its final day column was permanently empty; `/crm` custom ranges lost the last second.
  - **Verify at the endpoints, never the middle**: the two checks that catch every instance are (1) `from === to` returns that day's records, and (2) the LAST bucket/column of a series is non-empty when data exists for it. A range that looks right in the middle proves nothing.
- **Money always carries its currency symbol** (user directive 2026-07-19): every amount a user reads — KPI, table cell, chart axis, chart tooltip, table footer aggregate, i18n interpolation — renders through `formatMoney`/`formatMoneyShort` (`$lib/utils/format`). A bare `toLocaleString()`/`toFixed()` on a money field is a bug: "3,466,783" reads as a count, not soles (shipped: CRM revenue card, 4 socials pages, 11 stock surfaces, DataTable aggregates). Rules: (a) never hand-roll a local `fmtMoney`/`money()`/`soles()` — 6 divergent copies existed, each with different decimals and only some with a symbol; (b) where a helper is genuinely local (a page whose `fmt` serves BOTH qty and money), add a SEPARATE `fmtMoney` and leave quantities unit-less — do not blanket-format, or stock quantities grow currency symbols; (c) **currency is data, not a constant** — ad spend carries the ad account's ISO code (PEN or USD) and invoices carry `fin_invoices.currency`, so thread the row's currency and only fall back to the org default (`PEN`) when it's genuinely unknown; a mixed-currency aggregate must report `null` rather than guess; (d) ECharts money series need BOTH `tooltip.valueFormatter` and `yAxis/xAxis.axisLabel.formatter` — the axis is the easiest one to forget.

## Interaction & configurability contracts (standardized 2026-09-28 from hub #298–#400)

Owner taste extracted from the 2026-09-16 → 2026-09-28 window (100 hub commits). Each rule names the commit that landed it; treat the sha as the reference implementation.

### Records, links and hover cards
- **Record editor contract** (owner 2026-09-29, catalog editor in the modal): an EXISTING record autosaves — each field PATCHes only its change when focus leaves it, serialized per record through `createSaveStatus()` (`$lib/records/save-status.svelte.ts`) — so there is no Save/Cancel; the state shows in the TITLE BAR as `SaveIndicator` (Saving… → Saved → idle after ~1.5 s; error + Retry), reached through the peek context inside a peek and the page's own header outside one. Inside a peek the page hides its back button (`inPeek()`); the heading IS the record name, editable inline (keeps its `id` so the dialog's `labelledBy` still resolves); sections are flat and hairline-separated — never a card inside the dialog card. Create flows keep Save/Cancel (nothing exists to autosave yet).
- **The record's own text IS the link.** A customer name, a ticket number, a title: plain `<a>` (or a chrome-stripped ghost `Button`) — never a separate "Open"/"Open contact" button beside it (owner asked twice: `26eace6c`, `4003461f`). The open affordance is a glyph that slides in on `:hover`/`:focus-visible` and occupies no slot at rest (`opacity:0` + `translateX(calc(-1 * var(--space-1)))`, `--duration-fast`/`--ease-standard`): `.dt-open` in DataTable, `.hc-open` on the calendar hover card.
- **A record link must resolve to a route that has a `+page.svelte`** — register link and route in the SAME change; `src/lib/tables/title-links.test.ts` guards every `titleColumn` (`53640d6c` shipped a 404 on every catalog title).
- **One hover-card machine everywhere:** `Tooltip asChild interactive bare openDelay={180} closeDelay={320} id="<prefix>-<entityId>"` with a `content` snippet (`4003461f`, `bc3d97f4`). Never a hand-rolled floating div, never `title=""`. The stable per-entity `id` keeps one open card from stealing another's machine. A hover card says ONLY what its host surface does not already show (no repeating the customer name or total that sits under it). Nested interactive tooltips close their parent — a drag/reorder list lives INLINE in a Popover host, never inside a hover card (`bbcf1081` `FieldsList`).
- **A per-row exception is a tinted cell + delayed tooltip, not a badge** (`bg-warning/15` + `text-warning`, `Tooltip openDelay={400}` naming the threshold — `162fef88`). A badge inside a numeric cell competes with the number.
- **An actionable count is a labelled Button, never a lone number** ("Schedule 3" with an icon, `e82196bb`); a KPI that only repeats a list's count is deleted and the number moves onto that list's card header as a badge (`ea4979f6`).

### Trays, modals, confirms
- **Create/edit flows open the side tray as a FORM; the route stays only as a deep link.** The tray and the route render ONE shared panel component (`55f525c7` `AppointmentCreatePanel` ← `BookingCreateDrawer` + `/pos/appointments/new`). Trays/drawers = the native-`<dialog>` `Sheet` (`placement right|left|bottom`, `size sm|md|lg|xl`); modals are for ONE decision; a wide multi-column confirm takes `size="lg"` (`f76ca5a6`).
- **A destructive/structural confirm is ONE question with the facts and the way back:** `ConfirmDialog` + `details` snippet = a `dl` of what changes (before → after), one line of what does NOT change, one caption naming the undo. Never chain a second confirm for a consequence you can already state (`f87f3956`, `553b9011`).
- **Every DB-backed control paints optimistically with a pending state** (`createOptimistic()` + `Toggle pending`, `39cef0cf`); a drag/resize overlay retires on ITS OWN round trip, never on data identity (`2b09e0af` snapped back mid-request). Owner: visual feedback is the key to trust.
- **Status history = a chip timeline:** toned dot + `from` Badge → arrow → `to` Badge + one `t-caption` meta line, oldest first, on the SAME status ramp as the header badge (`2a23d912`).
- **A metered or side-effecting lookup fires on an explicit verb (a Find button), never on input; changing the input clears the previous answer** (`ed30400d` RUC lookup). **A field whose options depend on another field is DISABLED until that field is picked**, and its options narrow to the valid set (`c3e2b85d`, `8db726b2`).

### Configurability (the calendar/table contract shape)
- **Behaviours are a flag record with an explicit resolver that ignores `undefined`**, and every default reproduces the surface the component grew up on (`bc3d97f4` `calendar-features.ts` `resolveFeatures`). Spreading a partial record turns "not stated" into `false` at every call site.
- **`variant` is a PRESET only. Precedence = explicit prop > `chrome` > variant**, written into the prop's doc comment; nothing in the preset layer may override a value the caller passed (`0e5eac77` `chromeOn()`). Decompose bundles into named switchable chrome (`'search'|'columns'|'export'|'add'|'bulk'|'reorder'`) plus orthogonal knobs (`density`, `height: fill|fit|<length>`, `virtualize`, `stickyColumns`). A fixed-height wrapper div around a table is the smell this replaced. `variant="plain"` keeps `resizable: true` (owner directive `a7a7762c`).
- **Per-surface configuration lives in ONE toolbar kebab (⋯)**, never as extra toolbar buttons (calendar kebab: split, colour pickers, hover/block field lists, days-per-screen — `1a81d469`, `bbcf1081`; `features.kebab:false` drops it). Field lists are toggle + drag-reorder (`FieldsList`, the DataTable column-menu idiom).
- **Geometry = props that drive BOTH the JS arithmetic and the CSS custom properties, declared exactly once inline on the root** (`bc3d97f4` `--cal-*`). A JS constant plus a CSS copy drifts.
- **Per-column customisation is a keyed snippet RECORD (`cells`/`headers`) consulted before the single fallback snippet** (`0e5eac77`). Vocabulary is injectable (`statusTones`, `colorSources`, field catalogs); the root takes `class`/`style`/`...rest`; public CSS vars are listed in the component doc comment.
- **Generic page behaviour lives in a `kit/` beside the component as `create*` factories** (`scheduling/kit/`, `data-table/kit/` — `e74d7f9e`, `4e5350ce`), not in the page. **The URL is the contract**, mirrored through one coalesced `replaceState` per microtask from the CONSUMER's `$effect` calling `sync()` (a bare `$effect` never runs in this repo's vitest harness — false-green trap).
- **Per-viewer conveniences (colour source, days-per-screen, preview mode) = namespaced `localStorage` behind a factory (`createCalendarPrefs(ns)`), every read/write `try/catch`ed, and a refactor MUST preserve the key strings** (`e74d7f9e`). Preferences the user expects to FOLLOW them across devices (nav order, locale, landing page, record-overview visibility) = a `/api/me/preferences/<section>` section. Org-wide presentation (labels, hidden fields, ID prefixes, open mode) = `app_table_config` via `/settings/tables` (`b76d58f2`) — data, not code.
- **Every effect that resets scroll or refetches is keyed on the QUERY INPUTS as a signature string, never on derived rows or bindable objects** (`05bc2c2e`, `0e5eac77` — snap-to-top fired on every save).

### Tables
- Every table gets a read-only `idColumn` (org prefix + the HUMAN code, never the UUID; mono + caption + secondary; sorts on the raw code) and a `titleColumn` (the field that opens the record) (`b76d58f2`).
- Row actions live in the primitive's sticky trailing column whose wrapper swallows `click` + `pointerdown` — a row action never doubles as a row click; `rowActionsMode 'hover'|'always'`, hover includes `:focus-within` (`0e5eac77`). The sticky cell is TRANSPARENT and only its buttons are opaque; quiet states use COLOUR, never alpha (`ea4e93ad`, `5deb50ff` — content bled through `bg-bg/95` and `opacity:.6`); the actions column is the TRUE last column with a MEASURED width.
- **The open arrow is the ONLY way into a record** (owner 2026-09-29): a row click never navigates (`resolveRowOpen` defaults to `false`) — it used to fire out from under the tag/category pickers the same click opened. `.dt-open` is right-aligned in the title cell and OVERLAYS a narrow column on an OPAQUE surface (the row's own bg; never see-through); the title text stays a link.
- **Filters are Notion's** (spec `2026-09-29-hub-table-toolbar-notion-filters`): `+ Filter` lists EVERY column with a kind icon; a chip carries the column's type-aware operators (text contains/starts/ends/is/empty · number = ≠ > ≥ < ≤ between · date is/before/after/between/relative · select is-any-of/is-not · checkbox checked/unchecked); the advanced chip hosts the rule tree (And/Or, nesting, duplicate / wrap in group / turn into filter). `op` absent = the legacy default, so old literals and server tables keep working; server tables hide non-default operators. Grouping is a `GroupByPicker` (icon-only idle; icon + axis pill when active with a hover-revealed ×), hosted by the table toolbar via `groupOptions`.
- **Table options are per-user by default**: ⚙ writes the viewer's preference; applying org-wide is ONE explicit "Apply to everyone" behind a "…" kebab gated on `settings:manage` — never a For me / For everyone toggle. The header context menu keeps Sort/Wrap flat and nests Aggregate ▸ and Filter ▸ as flyouts.
- **Every cell is selectable, only editable cells edit** (owner 2026-09-29): in a table with any editable column, EVERY data cell takes the selection ring and keyboard navigation (arrows/Tab land on read-only cells too); opening an editor, typing, Enter, the fill handle and bulk edit stay gated per cell (`data-editable`). A custom cell that owns a picker (tags) has NO trigger of its own in a table — no "+ Add tag", no × on its chips: first click selects, second click or Enter opens the picker through `DataCellContext.open/onOpenChange`; the field variant outside tables keeps its add affordance (`showAdd`). Hotkey libraries that stop propagation by default (`@tanstack/svelte-hotkeys`) must be `enabled: !sel` or they swallow the grid's own keys (shipped: keyboard cell nav never worked).
- Filter chips are a built-in bar of removable chips + "Clear all" (`filterChips` default on), not per-page markup (`0e5eac77`). One verb per Picker row: a picked row shows the trash outright (`96fa8571`).
- A `<td>` is never `display:flex` (breaks the row box); `table-layout: fixed` + explicit widths; embedded tables contain their own overflow (`overflow-x: auto` on the card), never widen the page (`96fa8571`, `e80ac853`).
- The open cell editor drops its own border/background/radius/shadow — never nest chrome inside the selection ring; the ring is an `outline` with negative offset, not an inset `box-shadow` literal (`05bc2c2e`).

### Calendars and grids
- Create-by-gesture: a plain click on empty grid is INERT; press-and-drag draws a snapped ghost; double-click (or Enter on the focused layer) opens the form at the slot; month cells double-click only (`730d9239`). **Never tint a whole column/track on hover** — hover feedback belongs to the element that will respond to the click.
- Grouped items fan into a SIDE DECK beside their box, never inline over it, with a dim layer behind everything: the dim layer is the LAST child with NO z-index and is a real `Button` so the dismissing click is also the keyboard path (`dae46d27`, `dfbfad53`).
- **Fan-deck members drag** (owner 2026-09-29, `feat/pos-calendar-container-cancel-drag`): pointerdown on a fan block + a 4 px move threshold (a plain click still opens the drawer) with `setPointerCapture`; inside the deck's bounds the flex layout previews the new order live (`fanDragIndex`/`reorderPreview`, pure); release inside → `onreorder(id, ids)` restamps `groupSeq` without touching times; outside the bounds by 16 px the deck shows `data-drop="separate"` (outline warms to `--color-danger-fg`) and release runs the same `separate()` as the drawer action. Keyboard twins: `Alt+ArrowUp/Down` reorders, `Alt+Delete` separates. **A container's status is its ACTIVE members**: tone/strike/title come from the first member not cancelled/rejected/no-show (`box.statusLead`), the structural `box.lead` (seq 0) stays the id every call carries, and an "N cancelled" caption + struck members in the deck keep the inactive ones findable — never physically separate a cancelled member (a shared-window member has no slot of its own). **Status changes are optimistic** through the booking mover's `createOptimistic` overlay (`statusOf`/`pending`; revert + toast on failure).
- Infinite runways scroll on snap points and move their render window only on `scrollend`; the visible range is reported (`onrange`) so page filters can scope to it (`6716b276`, `0c1bbf32`).
- Surface-internal stacking = `isolation: isolate` + named LOCAL tiers (`--cal-tier-*: 1..4`); global `--layer-*` tokens only for what must beat app chrome (`e9e09685` → `bc3d97f4`). Sticky chrome is opaque with NO `backdrop-filter` (`7b1a451e`).
- Any toolbar gets a 44 px (`--control-height-touch`) floor on `button`/`select`/`[role=switch]` under `(max-width: 767.98px), (pointer: coarse)`, addressed BY ROLE so injected toolbar content is covered (`aed995b8`).

- **Record-detail card recipe** (`.card` + `.card-h` + `.kv`, copied per route until promoted — `4003461f`): `--color-surface-1` on `1px solid var(--color-border)` at `--radius-lg`; header = UPPERCASE `--font-size-caption` 600 `letter-spacing:.03em` `--color-text-secondary` `justify-content:space-between`; body `dl.kv` with `dt` secondary and `dd` `tabular-nums` right-aligned. ### Shipped-bug corollaries (guard tests exist — keep them green)
- **No scoped CSS may target a responsive-visibility utility** (`.nav-text:global(.hidden)` beat `hidden md:inline` and shipped a label-less sidebar, `70e370f0` → `0b860fbf`); key on the component's own state (`aside.is-collapsed`). Guard: `src/lib/styles/tailwind-utility-overrides.test.ts`. Measure ALL state × breakpoint combinations.
- **A list of control rows owns the column tracks** — every row (header included) is `grid-template-columns: subgrid; grid-column: 1/-1` (`11a41477`; generalises the bar-row contract to any control list).
- **`Button` inner-span trap, four more instances this window** (`bee0effa`, `66a7db24`, `d97fb5ff`, `dbaa7b80`): box-shaped Buttons need `:global(.cls > span)` overrides, a tall child needs explicit dimensions (`height:100%` inside the span has no definite height), and `Button` drops a caller's `role` — use `aria-pressed` inside `role="group"`.
- **A scoped `.parent > *` rule never reaches a child COMPONENT's root** — give the forwarded class `grid-column: 1/-1` + `contain: inline-size` (`813df897`). Zag: the layer goes on the CONTENT (`edcda4cc`); a panel born inside a native `<dialog>` portals INTO it via `use:portalInLayer` (`2ef60b78`); a machine whose trigger becomes `disabled` is CLOSED (`f623f593`); anchor + dismiss through the wrapper's `trigger` snippet, never `absolute right-0 top-full` + overlay hack (`142c4298`).

## Gates — run after EVERY UI change

```bash
cd minion_hub   # or minion_site
bun run lint:design    # debt ratchet: changed-file governed debt may only DECREASE (CI-enforced)
bun run lint:tokens    # every var(--x) must exist in contract/theme/registry
```

- Need an exception (illustration, theme-preview, syntax, data-visualization, third-party-render-surface)? Add to `scripts/design-lint-exceptions.json` with exact file+rule+**numeric cap**+category+reason. Caps, never blankets.
- Dynamic/runtime custom properties: register in `COMPONENT_INPUTS` or `THIRD_PARTY_RUNTIME_INPUTS` in `scripts/token-integrity.mjs` with a reason (fallback required).
- `--update-baseline` is decrease-only and will refuse increases.

## Extending the system

New semantic need → add token to `contract.json` with every theme mode enumerated → regenerate → release → consume. The `aliases` map is frozen by a deep-equal test (`tests/contract.test.mjs`) — adding one requires editing the test deliberately; `domainAliases` is the extensible bucket for temporary domain names. Name by role, not appearance; freeze the value table; alias only for migration.
